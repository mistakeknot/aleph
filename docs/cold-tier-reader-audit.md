# Cold-tier reader/writer audit: every code path touching `events`

> r3 corrections (after round-2 review): execution-request reads are reachable for archived threads through routes/threads/base.ts:508 and thread-execution-override.ts:209 (KEEP via the execution-request keeper). Lifecycle finalization is not live-only: deletion finalization (thread-lifecycle.ts:2045-2063) handles archived threads, but for a settled thread it only calls deleteThread and appends nothing. Fork has two entry services, `resolveThreadForkPoint` and `copyForkSourceHistory`; edit-message's entry is `editThreadMessage`. Classifications are bound to these entry functions, not to helper lines.

Read-only static audit, no builds or tests run.

Keepers (stay hot): newest row of the thread, all `thread/identity` rows, latest completed context-clear `system/operation` row (`THREAD_CONTEXT_CLEAR_OPERATION = "context_clear"`, packages/domain/src/thread-events.ts:165).

Class legend: KEEP = answerable from keepers, HYDRATE = needs cold rows, EXCLUDE = existing eligibility condition already keeps it off long-archived settled threads (or no prod callers), GLOBAL = cross-thread scan or sweep that silently misses/mishandles cold threads.
Paths below are relative to repo root. DB layer = packages/db/src/data. Server = apps/server/src.
Note: "hydrate" in `hydrateRetainedEventOutputRows*` (retained_event_outputs side table) is a different concept from cold rehydrate.
